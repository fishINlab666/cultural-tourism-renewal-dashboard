# 空间诊断地图工作台设计

## 目标

将八步流程中的第 3 步“空间诊断”改造成结果优先的左右分栏工作台。保留现有分析 Provider、六项诊断数据、证据版本和后续工程造价链路，不改变任何造价、投资或方案测算公式。

目标用户主要是政府、文旅主管部门和平台公司。页面应让非专业用户先理解项目位置、综合判断和需要关注的问题，再按需查看分析依据。

## 已确认方案

采用 A“结果优先”方案：

- 分析运行期间继续展示现有四阶段进度。
- 分析完成后收起大块进度卡，仅保留“集团数据综合分析 · 已完成”的轻量状态。
- 主结果区采用 60% 地图、40% 诊断总览的双栏结构。
- 默认无 Mapbox Token 时展示完整的本地浅色定位示意图；配置运行时 Token 后自动启用真实 Mapbox 浅色底图。

## 信息架构

### 页面标题区

继续使用工作区全局标题“空间诊断”。标题统一使用思源宋体优先的本机字体栈：

`"Source Han Serif SC", "Noto Serif CJK SC", "Songti SC", STSong, serif`

不增加远程字体请求。正文继续使用现有无衬线字体。

标题区右侧或副标题末尾显示分析状态：

`集团数据综合分析 · 已完成`

### 主结果区

桌面端主结果区比例为 `3fr 2fr`：

- 左侧地图占 60%。
- 右侧诊断总览占 40%。

页面宽度不足时逐级调整：

- 1080px 以下允许地图与右栏接近 55/45，优先保证雷达标签可读。
- 760px 以下改为纵向排列，地图在上，评分、雷达和结论在下。
- 地图容器预留固定最小高度，避免初始化时发生布局跳动。

## 地图设计

### 项目定位

演示项目为“三坊七巷历史文化街区”，不是单栋建筑。地图标记文案使用“当前项目中心点”，定位在福州三坊七巷南后街核心区域。实现时使用经过视觉核验的街区中心坐标，并在数据层保留可替换的 `longitude`、`latitude` 和 `label` 字段。

### 真实 Mapbox 状态

检测到运行时 `window.APP_CONFIG.mapboxAccessToken` 且 Mapbox GL 可用时：

- 使用 Mapbox 浅色底图。
- 初始镜头从较远尺度平滑飞向项目中心点。
- 项目中心点使用墨绿色自定义标记，并显示“当前项目中心点”标签。
- 地图仅提供基础缩放和移动，不加入搜索、图层切换或复杂 GIS 工具。
- 每次进入第 3 步时只执行必要的 `resize`；同一次页面会话不重复创建地图实例。

若用户开启“减少动态效果”，跳过飞行动画并直接定位。

### 无 Token 降级状态

默认状态不发起 Mapbox 请求，展示本地绘制的浅色街区示意图：

- 保留项目位置标签和墨绿色标记。
- 明示“演示定位 · 配置 Mapbox 后显示实时底图”。
- 视觉尺寸、信息层级和真实地图状态一致，避免页面出现空白区域或布局变化。
- 不在代码、日志、LocalStorage 或报告中写入 Token。

Mapbox 初始化失败、网络不可用或样式加载失败时，也切换到同一降级状态。

## 诊断总览

### 综合评分

右侧顶部显示综合评分 `82`：

- 数字为主要视觉焦点，墨绿色大号思源宋体。
- 首次进入已完成的空间诊断页时从 0 滚动到 82。
- 动画时长控制在 600 至 900ms。
- 减少动态效果模式下直接显示 82。
- 屏幕阅读器只读取最终结果“综合评分 82 分”，不播报中间数字。

综合评分作为分析结果中的显式字段保存，不通过修改现有造价或投资公式来凑分。

### 六维雷达图

使用 ECharts 雷达图，维度顺序固定为：

1. 区位潜力
2. 文化适配
3. 改造难度
4. 商业承载
5. 夜间潜力
6. 投资谨慎

数据映射如下：

- 区位潜力：现有“区位与导流潜力”。
- 文化适配：现有“文化适配度”。
- 改造难度：`100 - 工程可实施性`，当前演示值为 24，避免“越高越好”和“越高越难”混用。
- 商业承载：现有“商业承载力”。
- 夜间潜力：现有“夜间运营潜力”。
- 投资谨慎：现有“投资谨慎指数”。

图形采用墨绿色描边和低透明度填充，网格使用浅灰绿色。保留 tooltip，鼠标和键盘用户均可通过旁边的隐藏数据表获得六项数值。图表容器尺寸变化或步骤重新显示时调用 `resize`。

### 三条结论

右侧底部展示三条短结论，每条由状态图标、状态文字和结论组成，不能只依赖颜色传达：

- 绿色“优势”：区位与文化资源优势显著，适合低干预活化。
- 黄色“复核”：消防疏散、夜间噪声与居民影响需专项复核。
- 红色“谨慎”：建议分期投入，首开区先行验证客流与招商效率。

每条控制在两行以内。详细证据、版本和人工复核说明继续保留在主工作台下方的紧凑依据区域，不重新展开为原来的六张大卡。

## 组件与代码边界

预计涉及以下文件：

- `index.html`：替换第 3 步的结果区语义结构，并引入本地依赖文件。
- `styles.css`：新增地图工作台、评分、结论和响应式样式；更新标题字体栈。
- `app.js`：在步骤切换和分析完成后触发诊断工作台渲染。
- `data.mjs`：增加综合评分、地图定位和三条结论等演示结果字段。
- `diagnostic-view.mjs`：封装地图、评分动画、雷达图及实例生命周期。
- `vendor/`：保存项目所需的固定版本 Mapbox GL 与 ECharts 浏览器构建，避免通过 CDN 加载脚本。
- `tests/`：增加结构、数据映射、降级态和安全边界测试。

`diagnostic-view.mjs` 只接收结构化诊断结果和运行时配置，不读取造价、投资或方案状态，也不直接修改工作流。

## 数据流

1. `LocalAnalysisProvider` 返回原有六项诊断和分析版本。
2. 结果增加 `overview`，包含综合评分、地图定位和结论列表。
3. `app.js` 在第 3 步可见且分析完成时调用诊断视图模块。
4. 诊断视图模块渲染评分、雷达和结论。
5. 模块检测运行时 Mapbox Token：存在则初始化真实地图，不存在或失败则保持本地降级地图。
6. 离开第 3 步时保留实例；再次进入时只执行尺寸修正，不重复联网或重复飞行动画。

## 依赖与安全

- Mapbox GL 和 ECharts 使用固定版本的本地浏览器构建，不从 CDN 动态下载。
- Mapbox 底图在 Token 存在时必然需要访问 Mapbox 服务，这是本功能唯一新增的客户端网络行为。
- 仓库中只出现配置字段名，不包含 Token 值。
- 浏览器不连接集团数据库，不改变现有集团数据和 AI 的服务端边界。
- 测试继续禁止数据库地址、模型密钥和硬编码访问凭证。

## 错误处理

- 分析未完成：显示原有四阶段进度，不提前显示 82 分或结论。
- ECharts 未加载：显示六项可读数值列表，并给出“图表暂不可用”的非阻塞提示。
- Mapbox Token 缺失：显示本地示意地图，不显示错误横幅。
- Mapbox 初始化失败：自动回退到本地示意地图，并在地图角标提示“实时底图暂不可用”。
- 容器隐藏导致尺寸为零：延迟到第 3 步可见后初始化或调整尺寸。

## 测试与验收

自动化测试应先失败再实现，覆盖：

- 第 3 步包含 60/40 地图诊断工作台、综合评分、雷达容器和三条结论容器。
- 综合评分为 82，六维顺序和“改造难度”反向映射正确。
- 未完成分析时不展示最终评分和结论。
- 无 Token 时不尝试初始化 Mapbox，并保留可见降级地图。
- 有 Token 时 Mapbox 配置由运行时注入，不存在硬编码值。
- 重复进入第 3 步不会重复创建地图或 ECharts 实例。
- 减少动态效果模式下不执行飞行动画或数字滚动。
- 760px 以下变为纵向布局，不产生横向滚动。
- 标题使用思源宋体优先字体栈，正文保持现有字体。
- 原有造价和投资公式测试结果不变。

浏览器验收包括：

- 打开三坊七巷演示项目并进入第 3 步，确认地图区域、82 分动画、六维雷达和三条结论均可见。
- 在无 Token 环境确认降级地图完整、没有空白块。
- 调整桌面和移动端宽度，确认层级、标签和结论均可读。
- 检查控制台，无未处理异常和重复初始化警告。

## 非目标

- 本次不建设地理编码、项目搜索、多个建筑点位、GIS 图层管理或集团项目热力图。
- 本次不改变八步导航、分析 Provider 契约、造价模型、投资模型或三案逻辑。
- 本次不要求客户在页面内输入或保存 Mapbox Token。
